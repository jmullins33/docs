## What's in a prediction

Every Dirt IQ race prediction returns a ranked list of drivers with the following outputs for each:

| Output | Range | Description |
|---|---|---|
| `win_probability` | 0–1 | Probability of winning the feature event |
| `podium_probability` | 0–1 | Probability of finishing top 3 |
| `top5_probability` | 0–1 | Probability of finishing top 5 |
| `projected_finish` | Integer | Model's most likely finishing position |
| `form_score` | 0–100 | Rolling 30-day performance rating |
| `track_affinity` | 0–100 | Historical performance score at this venue |

All probabilities in a prediction sum to 1.0 across the driver pool for each category.

## Generating a prediction

```bash
POST /predictions
```

Minimum required fields are `event_id` and `division`. Optional fields let you tune the prediction:

```json
{
  "event_id": "evt_2024_eldora_4crown",
  "division": "late_model",
  "track_condition_override": 55.0,
  "include_heat_race_data": true
}
```

The response is available immediately — prediction generation typically takes under 300ms.

## Interpreting win probabilities

Dirt IQ win probabilities are **calibrated** — a driver with `win_probability: 0.20` should win roughly 20% of the time in similar conditions. This is verified against historical predictions monthly.

A few things to keep in mind:

- **Win probability rarely exceeds 0.30** in large, competitive fields. A driver at 0.25 in a 30-car World of Outlaws feature is strongly favored.
- **Sum-to-one constraint**: if one driver's probability rises (e.g., heat race showed dominant speed), others' probabilities decrease proportionally.
- **Long-shot value**: the model may assign non-trivial probability (0.05–0.10) to multiple drivers who are genuine podium threats but unlikely to win.

## Prediction lifecycle

Predictions are updated at key points in a race night. The `created_at` timestamp tells you when a prediction was last recalculated.

```
Entry list finalized      → Initial prediction
Hot laps / qualifying     → +qualifying adjustment
Heat race results         → +heat race adjustment (if enabled)
Feature start             → +starting position adjustment
Live timing (optional)    → Rolling lap-by-lap updates
```

Each update fires a `prediction.updated` webhook if you've registered one. See [Webhooks](/api-reference/endpoint/webhook).

## Head-to-head matchups

For a focused comparison between two drivers in the same event, use the matchup endpoint:

```bash
GET /predictions/{prediction_id}/matchup?driver_a=drv_9&driver_b=drv_17
```

Response:

```json
{
  "driver_a": {
    "driver_id": "drv_9",
    "name": "Donny Schatz",
    "win_probability": 0.19,
    "projected_finish": 2
  },
  "driver_b": {
    "driver_id": "drv_17",
    "name": "David Gravel",
    "win_probability": 0.16,
    "projected_finish": 3
  },
  "driver_a_beats_driver_b": 0.54
}
```

`driver_a_beats_driver_b` is the probability that driver A finishes ahead of driver B, useful for fantasy head-to-head contests.

## Polling vs. webhooks

| Approach | Best for |
|---|---|
| Poll `/predictions/{id}` on demand | Low-frequency integrations, dashboards that refresh on user action |
| Webhook subscription | Real-time apps, live overlays, fantasy platforms that need instant updates |

For live race-night applications, webhooks are strongly recommended. Polling more often than every 60 seconds on the same prediction ID is rate-limited.
